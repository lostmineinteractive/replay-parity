# Deferred

Items noticed during the build that are out of scope for the current step go here, each naming the step that raised it and what would change. Nothing here is required for `make demo`.

The six items this file held after Step 9 (compressed bodies, Redis Streams in CI, grouped top paths, agent dedupe granularity, prompt caching, and volume for latency cases) were done afterwards and are recorded in `CHANGELOG.md` under the heading for the work after Step 9. The items below were noticed during the two waves of the second enhancement round, `ENHANCEMENTS_2.md`, whose status table names what landed. Each names the enhancement that raised it.

- Progress during a replay (E3, E12). The engine reports progress only through its `onProgress` option, which the CLI does not wire, so a long replay prints nothing between the preflight lines and the summary. Observability, with a logger, progress lines, traces, and metrics, is being built now under E12 and is not deferred by this list; the item is here so the gap is named until that work lands.
- TLS flags on `rp agent` (E7, E9). The agent command has no `--upstream-ca`, `--upstream-cert`, `--upstream-key`, or `--upstream-insecure`, and neither do the capture proxy or the HTTP adapter, so a system behind a private CA needs `NODE_EXTRA_CA_CERTS`. The transport options are being built now under E7, and the agent command should take the same flags when they land, since it sends to both systems through the same adapter.
- `rp recording anonymize`, `diff`, and `migrate` (E2). `anonymize` waits on body redaction rules, which E1 has not delivered; `diff` waits on a decision about what two recordings compared under the rules should report; `migrate` waits on the manifest line, which does not exist. `rp recording` ships `validate`, `stats`, `filter`, `sample`, `split`, `merge`, and `scan`.
- The run file does not record the effective configuration (E11) or the agent's isolation mode (E9). `rp doctor` prints the configuration and profile in effect, and the agent transcript records the isolation mode under `isolation`, but a run file alone does not say which file, profile, or variables produced it or whether the agent's cases ran with resets or in parallel. A run store (E17) would need both to index runs, and `ENHANCEMENTS_2.md` named them as what the run should carry.
- `rp report` does not display `recording.recording_sha256` (E2). The field is in the run file and `rp shrink` checks it, and none of the five renderers prints it. Showing it in the header of the HTML, the terminal summary, and the Markdown would let a reader tie a report to a recording without opening the run file.
- A README per package for npm (E14). The eight public packages ship `dist/src`, the root `LICENSE`, and for core and agent their `schema/` and `prompts/`, and no package has a README of its own, so each package's page on npm carries only the `description` field of its `package.json`. `docs/release.md` describes the libraries, and a short README per package pointing there would be the fix.
- The root `Dockerfile` is untested (E14). `scripts/release-check.sh` builds the image only when a Docker daemon answers, and none was available when the release work was done, so the image has not been built on this machine. The release workflow builds and pushes it on the first version tag, which is where it will be exercised first; `make image` builds it locally once a daemon is available.
- The vitest worker stall on macOS (E15). On this machine a vitest worker stalls for about 9 seconds when another suite runs at the same time, which is what made synchronous tests of a few hundred milliseconds take 7 seconds and the three pacing tests fail before they were rewritten. The engineer's hypothesis is process scheduling or timer throttling of forked workers, and the options to try are `pool: threads` or fewer workers in the CI configuration. The timing policy in `docs/testing.md` makes the suite pass under the stall, and the root cause is open. Two tests still carry a plain elapsed bound that a stall of that length breaks: `reports a server that never answers as a timeout close to the configured deadline` in `packages/replay/test/chaos.int.test.ts` bounds the elapsed time at the deadline plus 700 ms inside a 5 second limit with no retry, and `ends at the upstream timeout, records the bytes seen, and names the exchange` in `packages/capture/test/proxy-upload-wait.int.test.ts` waits at most 5 seconds for the recording. Both should take the policy's generous commented bound and `retry: 2`.
- Lifecycle prerequisites for a filtered replay (E3, from the hardening table). `--filter tag=get-order` now pulls in the `create-order` exchanges that produce the ids, so no read mismatches on its id or status, but a read that followed a shipment, a cancel, or a quantity change in the recording still differs on `$.status`, `$.shipped`, `$.remaining`, `$.canceled_at`, `$.canceled_unshipped`, `$.items[0].qty`, `$.quantity`, and `$.total`, 27 mismatches on the committed recording, because nothing those reads use is a substituted value. Selecting every earlier command on the same order would need a lifecycle aware prerequisite rule beyond the substitution rules, and was left out; the test in `packages/replay/test/engine.int.test.ts` pins the remaining findings to those paths.
- Verifying the suite on Windows (E14). The `unit-matrix` job runs the unit project on `windows-latest` with `continue-on-error`, so its result is shown and never blocks a merge. Once a run there has been read and any path or line ending issue fixed, the job should block like the other two.
- A streamed request body is never retried (E1, accepted). The proxy pipes the client's body upstream as it arrives, and undici cannot retry a streamed body, so a request whose upstream connection fails mid upload is answered 502 and recorded as a failure rather than sent again. This was accepted when streaming landed and is noted here so nobody looks for a retry.
- The agent CLI test leaves two files in the working directory (noticed while verifying this round's documentation). The test in `packages/cli/test/agent.int.test.ts` that runs `rp agent` with a one cent budget passes no `--out`, so the default `generated-cases.jsonl` and its `agent-transcript.json` are written to the directory `pnpm test` runs from and are left behind, untracked. The test should write into its temporary directory like the others in that file.
