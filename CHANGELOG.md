### Enhancements, round two: waves one and two

The work proposed in `ENHANCEMENTS_2.md` landed in two waves of engineering after commit `62046e5`. One entry per theme. The status of each proposal is at the top of that document.

- Capture streaming bodies and query redaction. The proxy no longer buffers a sampled response in full before the cap or reads a request body in full before forwarding. `CappedBody` keeps a running SHA-256 and byte count of every chunk and drops the kept chunks once the count passes `--max-body-bytes`, so a body of any size costs at most the cap in memory. Within the cap the kept bytes go through `encodeBody` as before, so JSON parsing, decoding, and the decoded size cap are unchanged. Over the cap the body is stored as the hash and size of the wire bytes with its codings noted, through the new `truncatedBodyFields` in core, which `encodeBody` now uses for a compressed body over the cap as well. The client's request body is piped through a Transform that undici sends upstream, so the reference receives the bytes as they arrive; the client's content length is forwarded when present, a chunked body stays chunked, a request without a body still sends none, and a client that goes away mid body fails the upstream request with it. Undici cannot retry a streamed body, which is accepted. `redactQuery` in core replaces the value, or every value, of a query parameter whose lower cased name is listed, keeping the key as written, and `DEFAULT_REDACTED_QUERY` names the usual token parameters: `api_key`, `apikey`, `access_token`, `token`, `key`, `secret`, `signature`, and `password`. `rp capture --redact-query <name>`, repeatable, replaces that list the same way `--redact-header` does, and the candidate recording applies `redactQuery` to the request as sent, so it never holds a cleartext token either. Unit tests cover `CappedBody`, `redactQuery`, `truncatedBodyFields`, and the query list on `candidateExchanges`; integration tests cover the proxy streaming a request body over the cap to the upstream intact, a chunked request body, a small JSON body and an empty one, a compressed response capped on its decoded size, and query values redacted by the default list and by a custom one while forwarded in clear.

- The clean stop on a signal, the gap cap, dependency selection, the version, and `.env` resolution. The first SIGINT or SIGTERM aborts one controller that `buildProgram` passes to every command, and a second signal exits at once with 130. `ReplayOptions` takes `signal`: on abort the scheduler sends nothing more, the sends in flight are aborted through the shutdown controller, the run finishes with the results so far, exchanges never sent are left out, a scheduled wait ends early, and the run carries an `aborted` condition, a new run level inconclusive kind, naming how many of the selected exchanges were sent, so a replay stopped by a signal writes the partial run and exits 3. `ShrinkOptions` takes `signal`: the attempt in progress is cut short and not judged, the best reduction found so far is kept, the reduced recording is still written, and the command says it was stopped and exits 3. `AgentOptions` takes `signal`: the loop checks it before each round and before each case, stops with the stop reason `aborted`, writes the transcript, the cases, and the agent section, and exits 3; a signal already aborted stops before the first model call. `--max-gap-ms <n>` (default 30000, 0 disables) is applied in `buildSchedule` under `as-recorded` only: each gap above the cap is reduced to the cap, the requested rate is computed over the capped schedule, the run records `max_gap_ms` and `gaps_capped` in `pacing`, and `rp replay` prints one line when gaps were capped. `includeDependencies` (default true) makes a filtered replay with substitution rules also select the transitive producers of every captured value the filtered exchanges use, through `DependencyIndex` over the full recording; they are replayed and acknowledged for ordering and substitution, marked `dependency: true`, and excluded from statistics and thresholds like warmup exchanges, and `--no-include-dependencies` turns that off with a line naming how many were selected. The first run of the properties found three defects, each recorded as an `it.fails` test with the exact inputs until it was fixed. First, a keyed `unordered` rule rendered `[name=value]` with the key name and value unescaped, so a key holding a quote mark, whitespace, `]`, or a non scalar, a row without the key that is an array, or a key path in bracket form gave a finding path `parsePath` rejected; `keyValueText` now renders a string bare only when it is a plain token and as a JSON string in double quotes otherwise, an array or object renders as its canonical JSON in single quotes, a keyed name that is not an identifier is quoted, the marker for a row without the key carries the row's canonical JSON behind `#`, and the parser reads every quoted form back, so every body finding path under any rules reads back as itself. Second, `keyValueText` rendered the number `1` and the string `"1"` as the same text, so under a keyed rule the rows `{ sku: 1 }` and `{ sku: "1" }` shared one group and the differ reported type findings; a string now renders bare only when it is an identifier other than `true`, `false`, and `null`, so a bare text starts with a letter, `_`, or `$` exactly when it is a string. Third, `decodeContentEncoding` held every coding layer to the cap, so ten bytes under `gzip, br` with cap 10 were truncated while the same ten bytes under `gzip` alone were stored; the cap now applies to the final decoded size only, an intermediate layer may reach 64 times the cap and at least 16 MiB, and a decompression bomb still stops with `ERR_BUFFER_TOO_LARGE` and is stored as truncated. - The capture upload bound and the timing policy. The proxy awaited the upload stream's close after the response ended, trusting undici to end, reset, or fail it. The wait now races the upstream timeout: on timeout the stream is destroyed, the exchange is recorded with the bytes the tee saw, and `onError` names the exchange. Once the stream closes with the request incomplete, the rest of the body is read and discarded, as Node does for an unconsumed body, so the connection is not left paused on unread bytes and a client that leaves is noticed, and a response that fails mid body also destroys the upload stream. Undici 8 resets the socket whenever the response completes while the body is still being written, so the bound is not reachable through a real upstream; the test replaces the pool with a stand in that reads one chunk, answers, and never touches the stream again. ### After Step 9: the deferred items

- Compressed bodies. The capture proxy and the HTTP adapter decode a body that arrived with a `content-encoding` of gzip, deflate (zlib wrapped or raw), or br before storing it, and note the codings in a new optional `content_encoding` field on the request or response. The body is then stored by the existing rules, so a compressed JSON response is stored parsed and two systems that compress differently compare equal when their decoded bodies are equal. The size cap applies to the decoded size, a decoded body over the cap is stored as the hash and size of the bytes as received, and a coding the harness cannot undo or data that does not decode is stored as received with no note. On replay the HTTP adapter puts a request body with `content_encoding` back on the wire with the coding applied again, so the bytes match the recorded `content-encoding` header. The proxy still streams the compressed bytes to the client untouched. The JSON Schema is regenerated. Tests cover each coding, stacked codings, identity, unknown and corrupt input, the cap, the wire round trip, the schema refinement, the proxy with a compressed response and a compressed request body, and the adapter in both directions.

### Step 8: the agent

- Added `@replay-parity/agent`. `runAgent` runs the loop from the spec: each round summarizes the run (verdict, threshold rows that did not pass, mismatches by tag, mismatching paths with array indices generalized, a sample of mismatched exchanges, failed latency rows), describes one request shape per tag from the recording, lists the kept cases so far, asks the model for up to `--cases-per-round` cases as one JSON object, validates them, sends each to the reference and the candidate, diffs the final responses, and keeps a case when it reveals a mismatch path set or a latency breach that no kept case already reveals. It stops when a round adds nothing new, the budget would be crossed, the round limit is reached, every case in a round is invalid, the model declines, or a call fails.
- Cases are one to three steps. A step may capture a value from its response and later steps may use it as `{{name}}` in the path, query, or body. Captures resolve separately on the reference and the candidate, and the captured pairs feed the differ as equivalences, so a create then get sequence reads each system's own id and the ids do not count as a difference. A JSON body goes out with `content-type: application/json` when the case did not set it. Validation drops malformed JSON, schema violations, unknown tags, more than three steps, a placeholder no earlier step captured, and a redacted header name carrying anything but the redaction marker, each with a reason in the transcript.
- The model never sees secrets. The request shapes show only `content-type` and `idempotency-key` values. Any other header is left out, and a header on the redaction list is shown as the marker even when the recording was not redacted. Prompts are built from the run, the recording, the rules, the thresholds, and the kept cases, and never from the repository tree.
- `ModelClient` is a plain text contract. `AnthropicModelClient` wraps `@anthropic-ai/sdk` with adaptive thinking, `output_config.effort` `medium`, `max_tokens` 8192, and the model `claude-sonnet-5-5` by default, maps `stop_reason: refusal`, and accepts a `fetch` override for tests. `MockModelClient` answers from a script. A static pricing table turns usage into dollars per call and in total, with a conservative estimate before each call that stops the loop when a call could cross the budget. An unlisted model is priced like the most expensive listed one and the transcript says so.
- Prompts live in `packages/agent/prompts/system.md` and `round.md`, are versioned by content hash, and the versions are written to the run and the transcript. The transcript holds the system prompt, each round's user prompt, the model's text, usage and cost, the dropped cases with reasons, the executed cases, the kept ids, and why each other case was not kept.
- `rp agent` reads `ANTHROPIC_API_KEY` from the environment, then from the file named by `--env` (default `.env`) when the variable is not set, and without a key prints a message and exits 0 without building a client. With a key it runs the loop, writes `generated-cases.jsonl` and `agent-transcript.json` next to it, and adds the `agent` section to the run in place. Flags: `--run`, `--recording`, `--target`, `--reference`, `--rules`, `--thresholds`, `--out`, `--cases-per-round`, `--model`, `--budget-usd`, `--max-rounds`, `--header`, `--headers-file`, `--timeout-ms`, `--env`. `make demo` runs it after the first replay when the key is present and renders `report.html` again.

Two CLI tests cover the no key path without a client and the loop through the command with an injected client, including that the key never appears in the output or the transcript.

### A4: shrinking (Addendum A4)

- Added `@replay-parity/shrink`. `shrink(options)` takes a recording, a candidate target, a reset hook, and a failing rule, and returns a reduced reproduction. The rule is either an invariant on one system (`invariant:<system>:<name>`) or a mismatching exchange with an optional finding path (`mismatch:<exchange id>[:<path>]`). `defaultRule(run)` picks the first violated candidate invariant, then the reference, then the first mismatching exchange.
- The algorithm. Steps after the witnessing exchange are dropped first. Delta debugging in the complement form then removes chunks of the remaining steps, and a prerequisite closure re-adds what any kept step needs: the create that produced an order id used in a path, and the producers named by the substitution rules. Relative order never changes and shipment ids are never renamed. For a candidate invariant a second pass lowers `qty` and `quantity` values toward one with a binary search per field. Every candidate reduction is replayed at `max` pacing with one request in flight against a candidate reset through the hook, and judged by the same rule. An attempt whose run is inconclusive counts as not reproduced.
- Bounds. `maxAttempts` (default 64) and `timeBudgetMs` (default 120000). When the budget runs out the best reduction confirmed so far is kept. When the first attempt does not reproduce, the original is kept and the label is `reduction unsuccessful`.
- Core: the run gains a nullable `reproduction` section with the rule, original and reduced step counts, attempts, `successful`, the label (`reduced reproduction` or `reduction unsuccessful`), the duration, the path of the reduced recording, and the steps with their bodies and a `quantity_reduced` flag. The JSON Schema is regenerated.
- Replay: `replayExchanges(exchanges, options)` replays a list held in memory and returns the run without reading a file. `replay(path, options)` reads the file and calls it. `writeExchanges` is exported.
- Tests: 15 in the package. Unit tests cover delta debugging with and without a closure, chunking, the budget error, rule parsing and formatting, the default rule, the judge, and the prerequisites. Integration tests shrink the committed recording against the candidate: the duplicate shipment defect reduces from 283 steps to at most five that still trip invariant 1 when replayed from the written file, the dropped pre cancel shipment reduces to create, cancel, and shipment, a rounding mismatch reduces to the single create that shows it, a rule that does not reproduce keeps the original, and both budgets stop the search while keeping what was confirmed.

### A1: independent invariants (Addendum A1)

- Added `@replay-parity/invariants`. `evaluateInvariants(exchanges)` evaluates the ten invariants against one system's recording and nothing else. A command parser maps exchanges to creates, cancels, quantity changes, shipments, stock adjustments, restarts, resets, and reads. A model rebuilds the expected state from the system's own acknowledgements: a command counts when the system answered 2xx, a rejected command is never applied, and a retried command is applied once. An accepted reset starts a new epoch and rules run per epoch.
- The rules, one file each, return `holds`, `violated`, `not_applicable`, or `inconclusive` with evidence naming the subject, the expected and observed values, and the witnessing exchange. Invariants 1 and 4 compare every order view with the expected quantity, shipped, remaining, and unshipped canceled quantity. Invariant 4 also expects a shipment that originated before the cancellation to be accepted and a later one to be rejected. Invariants 5 and 6 compare stock and receivable deltas between consecutive reads with the accepted adjustments and unique accepted shipments in that interval, so a shipment applied twice is localized to the interval where it happened. Invariant 5 reads initial stock plus accepted adjustments minus unique shipments. Invariants 8 and 9 check idempotency keys, retries, and order counts across the restart. Invariant 10 recomputes each allocation from a stock baseline derived from the first read of the SKU and the quantities live orders still have to ship.
- The completion check. When a state changing command was sent before the final ledger read and acknowledged after it, the report carries `snapshot_before_ack` and the run is inconclusive.
- Core: `InvariantReport` and its schemas, an `invariants` section on the run with `reference` and `candidate` reports, a `candidate_recording` path on the run, `invariants.fail_on_violation` in the thresholds file (default true), and threshold rows `invariants.reference.violations` and `invariants.candidate.violations`. The run JSON Schema is regenerated.
- Replay: the `invariants` option evaluates both recordings after the run, fills the section, forwards each report's inconclusive conditions, and feeds the violation counts to the thresholds. The engine now builds the candidate's observed log once and writes it when `--candidate-recording` is set.

### Step 4: replay engine

- Added `@replay-parity/replay`. `replay(options)` reads a recording, selects exchanges by tag and limit, sends them through an adapter on one of three schedules, diffs every response against the recorded one, aggregates statistics, evaluates the thresholds, and returns the run. `as-recorded` keeps the recorded gaps, `fixed-rate` spaces sends at `--rps`, and `max` sends as soon as a slot in the pool is free. Each exchange result carries `scheduled_at_ms`, `sent_at_ms`, and `acked_at_ms`, and the run carries requested and achieved rate with schedule slip p50 and max.
- Substitutions. A `DependencyIndex` computes, before anything is sent, which earlier exchange produces each captured value a request uses, and the engine waits for those producers under every pacing mode. A `SubstitutionTable` records reference to candidate pairs as exchanges complete, rewrites later paths, query values, and body leaves, and feeds the differ its equivalences so a mapped id is reported as tolerated by `substitution:<name>`. The first exchange to produce a reference value wins, so a retried command that yields a different candidate id is a mismatch rather than a silent remap.
- Barriers. `--barrier-tag` (repeatable) and `--barrier-timeout-ms` (default 10000). An exchange with a barrier tag waits until every earlier exchange has a response or an error, is sent alone, and is acknowledged before anything later is sent. A wait longer than the timeout records `barrier_timeout` and the run is inconclusive. The run records `barrier_tags`, `barrier_timeout_ms`, and `barrier_waits`.
- Harness controls. The rules file gains `controls.tags`. An exchange carrying one of these tags is a barrier, is diffed on status only through the new `differ.diffStatus`, is excluded from statistics and from every threshold, and is written to the run with `control: true` so the report can show it in sequence without scoring it. A control that fails or answers a different status makes the run inconclusive with the new kind `control_failed`.
- HTTP adapter on an undici pool. Sends the recorded method, path, query, headers, and body, drops hop by hop headers, the host, the content length, and any header whose recorded value is `<redacted>`, applies caller supplied headers over recorded values, measures latency from dispatch to the last body byte, enforces the timeout through an abort signal so the deadline is exact, and classifies failures as `timeout`, `connection`, `aborted`, `protocol`, or `other`.
- Bus adapter over a `MessageBus` interface with string payloads. `InProcessBus` delivers asynchronously in publish order. `RedisStreamsBus` publishes with `XADD` and reads with a blocking `XREAD` on a dedicated connection, loading the `redis` client on first use. The adapter publishes a request envelope with a correlation id to `rp.requests.<first path segment>` and awaits the reply envelope on its own reply topic. `serveBus` is the responder side, used by the tests and documented as the contract for a system under test.
- `--candidate-recording <path>` writes the requests as sent and the candidate responses as a second recording in the same format, in send order, with the reference exchange ids and tags, and with the capture redaction list applied to headers. Failed sends are left out.
- Warmup exchanges run but are excluded from statistics. Transport failures are recorded as `error` with a null candidate and a null diff. A truncated recorded body is never diffed and yields one `body_too_large` finding that counts as a mismatch.
- Core: `DiffRulesSchema` gains `controls.tags`, `Differ` gains `diffStatus`, `InconclusiveKind` gains `control_failed`, and the run JSON Schema is regenerated.
- Tests: 42 across the package. Unit tests cover the schedules, slip summary, dependency index, substitution table, header and query helpers, both buses, and the bus adapter. Integration tests run the committed recording against the candidate in process: the clean pair passes with zero mismatches and a valid run and candidate recording, shifted ids pass through substitutions, barriers hold order under concurrency, the four classic divergences are found and the `adjust-stock` p99 gate fails with the seeded delay, filter and limit and warmup apply, each pacing mode holds its schedule, a barrier timeout and a failed control make the run inconclusive, transport failures are recorded, and caller supplied headers override recorded ones. The Redis Streams test runs when `REDIS_URL` is set.
- Added `DEFERRED.md` for work noticed during the build that is out of scope for the current step.

### A2: inconclusive verdict in core (Addendum A2)

- The run verdict is now `pass`, `fail`, or `inconclusive`. A new `inconclusive` array on the run lists the triggering conditions, each with a `kind` (`barrier_timeout`, `snapshot_before_ack`, `schedule_not_held`, `insufficient_samples`) and a `detail` string. `decideVerdict` in `run/verdict.ts` applies the precedence rule: a run level condition makes the run inconclusive even when mismatches were observed, otherwise any failed threshold or invariant violation makes it fail, otherwise any insufficient sample row makes it inconclusive, otherwise it passes. `EXIT_CODES` maps pass to 0, fail to 2, inconclusive to 3, and tool error to 1.

A latency row with fewer successful candidate samples than its minimum, a `by_tag` entry whose tag is absent, a correctness row with nothing compared, and an error rate row with no samples are inconclusive rather than failed. A ratio row with a zero reference value still fails, since that is a fact about the data.

When `slip_max_ms` is set and the replay's largest schedule slip exceeds it, the run is inconclusive with `schedule_not_held`. When unset, slip is reported and never triggers.

Step 4 fills them. `control: true` marks a harness control such as a restart, which is replayed in order and shown in sequence but never scored. - Added a JSONPath subset (`$`, `.name`, `['name']`, `[n]`, `[*]`, `.*`) with concrete path rendering, wildcard rule matching, and keyed segments for unordered arrays.
- Added the diff rules schema with `ignore`, `tolerances`, `unordered` (list of `{path, key}` objects), `status.equivalent`, `headers.compare`, and `substitutions`, plus YAML loading that names the file and the path of any error.
- Added the differ with `match`, `tolerated`, and `mismatch` verdicts, deterministic finding order, substitution equivalences, the `body_too_large` finding for truncated bodies, and plain language explanations.
- Added latency statistics on `hdr-histogram-js` with fixed log spaced bins, per tag and overall aggregation, the thresholds schema and evaluator, and the run model with its JSON Schema emitted to `packages/core/schema/run.schema.json`.
- Added a `testing` module with fixture builders and an ajv based run validator for use by other packages' tests.
- Set Prettier to single quotes.

### Step 0: workspace scaffold

- Added the pnpm workspace with `packages/*` and `demo/*`, a shared strict TypeScript base config with project references, ESLint flat config with type checked rules, Prettier, and a Vitest root config with `unit` and `integration` projects and a 90 percent coverage gate on `packages/core`.
- Added the MIT license, a Makefile compatible with GNU Make 3.81, and empty shells for the six packages and the two demo services.
- Added `scripts/check-prose.sh`, which fails on em dashes in Markdown and on banned vocabulary anywhere in the tree, and `scripts/check-secrets.sh`, which fails when a git visible file contains an Anthropic API key prefix and prints only file names and line numbers.
- Pinned TypeScript 6.0 because typescript-eslint does not yet accept TypeScript 7. Pinned `@types/node` 22 to match the supported Node version.
