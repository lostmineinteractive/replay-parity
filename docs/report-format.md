# The run file

`rp replay` writes `run.json`. It is the canonical report. `rp report` renders HTML and the terminal summary from it, `rp shrink` and `rp agent` add their sections to it in place, and `rp report --format json` validates it and prints it again. The JSON Schema, draft 2020-12, is generated from the zod definitions in `packages/core/src/run/schema.ts` and committed at `packages/core/schema/run.schema.json`. A test fails when the two drift apart.

## Top level

| Field                 | Type                           | Meaning                                                                                                                                                                                                                                                                                                                                                        |
| --------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schema_version`      | `1`                            | Bumped on an incompatible change.                                                                                                                                                                                                                                                                                                                              |
| `run_id`              | ULID                           | Unique per run.                                                                                                                                                                                                                                                                                                                                                |
| `created_at`          | ISO 8601                       | When the run was written.                                                                                                                                                                                                                                                                                                                                      |
| `verdict`             | `pass`, `fail`, `inconclusive` | The outcome, by the precedence rule below.                                                                                                                                                                                                                                                                                                                     |
| `inconclusive`        | array                          | Why the run is inconclusive. Empty otherwise. Each entry has `kind` and `detail`.                                                                                                                                                                                                                                                                              |
| `recording`           | object                         | `path`, `exchanges` in the file, `selected` after filter, dependencies, and limit, `first_ts`, `last_ts`, and `recording_sha256`: the SHA-256 of the file's bytes, null when the engine was given exchanges in memory and absent in a run written before the field existed. `rp shrink` refuses a recording whose hash differs. See `docs/recording-tools.md`. |
| `target`              | string                         | The candidate's base URL.                                                                                                                                                                                                                                                                                                                                      |
| `adapter`             | string                         | `http` or `bus`.                                                                                                                                                                                                                                                                                                                                               |
| `pacing`              | object                         | See below.                                                                                                                                                                                                                                                                                                                                                     |
| `warmup`              | integer                        | Leading exchanges that ran but did not count.                                                                                                                                                                                                                                                                                                                  |
| `filter`              | object                         | `tag` or null, `include_dependencies`, and `dependencies`: how many exchanges were pulled in because a filtered exchange uses a substituted value they produce.                                                                                                                                                                                                |
| `limit`               | integer or null                | The cap applied after filtering.                                                                                                                                                                                                                                                                                                                               |
| `duration_ms`         | number                         | From the first send to the last acknowledgement.                                                                                                                                                                                                                                                                                                               |
| `rules`               | object                         | The diff rules that were applied, in full.                                                                                                                                                                                                                                                                                                                     |
| `thresholds`          | object                         | The thresholds that were applied, in full.                                                                                                                                                                                                                                                                                                                     |
| `threshold_results`   | array                          | One row per configured limit. See below.                                                                                                                                                                                                                                                                                                                       |
| `stats`               | object                         | Latency and correctness statistics overall and per tag. See below.                                                                                                                                                                                                                                                                                             |
| `exchanges`           | array                          | One result per selected exchange. See below.                                                                                                                                                                                                                                                                                                                   |
| `candidate_recording` | string or null                 | Path of the candidate's observed log when `--candidate-recording` was given.                                                                                                                                                                                                                                                                                   |
| `invariants`          | object                         | `reference` and `candidate`, each an invariant report or null.                                                                                                                                                                                                                                                                                                 |
| `reproduction`        | object or null                 | Filled by `rp shrink`.                                                                                                                                                                                                                                                                                                                                         |
| `agent`               | object                         | Present after `rp agent`.                                                                                                                                                                                                                                                                                                                                      |

Schema versions. `rp` migrates an older run file when it reads one: before validating against the schema, it applies one migration per version step from the file's `schema_version` up to the current one, so a file written by an earlier `rp` still renders and can still be extended by `rp shrink` and `rp agent`. A file whose `schema_version` is higher than the one this `rp` knows is refused with an error saying it was written by a newer version of `rp`, and a file with no integer `schema_version` is refused with an error naming that. The migrations live in `packages/core/src/run/migrate.ts`, one entry per source version in `RUN_MIGRATIONS`; the table is empty while version 1 is current.

## Verdict and inconclusive kinds

The precedence rule: a run level condition makes the run inconclusive even when mismatches were observed. Otherwise any failed threshold row makes it fail. Otherwise any insufficient sample row makes it inconclusive. Otherwise it passes.

| Kind                   | Run level | Set when                                                                                                                                      |
| ---------------------- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `barrier_timeout`      | yes       | An exchange with a barrier tag waited longer than `--barrier-timeout-ms` for earlier exchanges.                                               |
| `snapshot_before_ack`  | yes       | The final ledger read was sent while an accepted state changing command was still in flight. Reported by the invariants.                      |
| `schedule_not_held`    | yes       | The largest schedule slip exceeded `pacing.slip_max_ms`.                                                                                      |
| `control_failed`       | yes       | A harness control errored or answered a different status.                                                                                     |
| `aborted`              | yes       | The run was stopped by SIGINT or SIGTERM. The detail says how many of the selected exchanges were sent; the rest are left out of `exchanges`. |
| `insufficient_samples` | no        | A threshold row could not decide: fewer successful samples than `min_samples`, a tag with no samples, nothing compared, or no samples at all. |

## Pacing

| Field                        | Meaning                                                                                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mode`                       | `as-recorded`, `fixed-rate`, or `max`.                                                                                                                       |
| `rps`                        | The requested rate under `fixed-rate`, else null.                                                                                                            |
| `concurrency`                | Most exchanges in flight at once.                                                                                                                            |
| `requested_rps`              | The rate the schedule asked for: the recording's own rate over the capped schedule under `as-recorded`, `rps` under `fixed-rate`, null under `max`.          |
| `achieved_rps`               | Exchanges sent divided by the duration.                                                                                                                      |
| `slip_p50_ms`, `slip_max_ms` | Median and largest of actual send time minus scheduled send time, over non control exchanges.                                                                |
| `barrier_tags`               | The barrier tags in effect.                                                                                                                                  |
| `barrier_timeout_ms`         | The timeout in effect.                                                                                                                                       |
| `barrier_waits`              | How many times a barrier found earlier exchanges still in flight.                                                                                            |
| `max_gap_ms`                 | The cap on a recorded gap under `as-recorded`, from `--max-gap-ms` (default 30000). Null when `--max-gap-ms 0` disabled it or the mode has no recorded gaps. |
| `gaps_capped`                | How many recorded gaps were longer than the cap and were reduced to it.                                                                                      |

## Threshold rows

Each row has `id` (such as `latency.by_tag.create-order.p99_ms`), `section` (`latency`, `correctness`, `errors`, `pacing`, `invariants`), `scope` (`overall`, a tag, or a system), `metric`, `limit`, `measured` (a number or null), `outcome` (`pass`, `fail`, `inconclusive`), and an optional `detail` such as `3 successful samples, minimum 20`.

## Statistics

`stats.overall` and `stats.by_tag.<tag>` have the same shape: `count`, `errors`, `error_rate`, `compared`, `matches`, `tolerated`, `mismatches`, `mismatch_rate`, `candidate` and `reference` latency summaries (`count`, `p50_ms`, `p90_ms`, `p99_ms`, `p999_ms`, `max_ms`, `mean_ms`), and `histogram` with `candidate` and `reference` bin counts. `stats.histogram_edges_ms` holds the 49 edges of the 48 log spaced bins from 0.1 ms to 10 s, so the HTML renders the histograms without a library. Warmup and control exchanges are excluded. Reference latencies come from the recording.

## Exchange results

| Field                                          | Meaning                                                                                                                                                                                                                       |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`, `tags`, `method`, `path`                 | From the recording. The path is the recorded one, before substitution.                                                                                                                                                        |
| `warmup`                                       | True for the leading warmup exchanges.                                                                                                                                                                                        |
| `control`                                      | True for a harness control.                                                                                                                                                                                                   |
| `dependency`                                   | True for an exchange selected only because a filtered exchange uses a substituted value it produces. Replayed and acknowledged for ordering and substitution, excluded from statistics and thresholds like a warmup exchange. |
| `scheduled_at_ms`, `sent_at_ms`, `acked_at_ms` | Milliseconds since the run started. `acked_at_ms` is null on an error.                                                                                                                                                        |
| `reference`                                    | `status` and `latency_ms` from the recording.                                                                                                                                                                                 |
| `candidate`                                    | `status` and `latency_ms` from the replay, or null on an error.                                                                                                                                                               |
| `error`                                        | `kind: message` on a transport failure, else null. Kinds: `timeout`, `connection`, `aborted`, `protocol`, `other`.                                                                                                            |
| `diff`                                         | `verdict` (`match`, `tolerated`, `mismatch`) and `findings`, or null when not compared.                                                                                                                                       |

A finding has `path` (a concrete JSONPath, `status`, or `header:<name>`), `kind` (`status`, `header`, `value`, `type`, `missing`, `unexpected`, `body_too_large`, `body_format`), `tolerated`, and optional `reference`, `candidate`, `rule`, and `detail`. A row matched under a keyed `unordered` rule appears in the path as `[name=value]`, as in `$.items[sku=A-100].qty`. The key value is bare for a string that is a plain identifier such as `A-100` and for a number, `true`, `false`, or `null`, a JSON string in double quotes for any other string, as in `$.items[sku="a b"].qty` and `$.items[sku="1"].qty` for the string `1` against `$.items[sku=1].qty` for the number, and the canonical JSON in single quotes for an array or object, as in `$.items[sku='[1,2]'].qty`; the name is quoted as a JSON string when it is not an identifier; the nth later row with the same key carries `#n` after the value, as in `[sku=A-100#1]`; and a row without the key is grouped by its own canonical JSON in single quotes behind `#`, as in `[sku=#'{"qty":3}']`. Every finding path reads back through the harness's JSONPath parser.

Bodies in the recording and in the candidate recording follow one rule set. A JSON content type is stored parsed in `body`. Anything else is stored as base64 in `body` with `encoding: "base64"`. A body over the size cap is stored as `truncated: true` with `body_sha256` and `body_size`. A body that arrived with a `content-encoding` of gzip, deflate, or br is decoded first, stored by the same rules, and carries `content_encoding` with the codings undone, in the order they were applied. The cap applies to the decoded size, and a truncated body's hash and size always describe the bytes as received. A coding the harness cannot undo, or data that does not decode, is stored as received with no note.

## Invariant reports

Each report has `system`, `recording`, `exchanges`, `commands`, `snapshots` (`ledger_reads`, `stock_reads`, `order_reads`), `results`, `violations`, and `inconclusive`. Each result has `id` (1 to 10), `name`, `statement`, `status` (`holds`, `violated`, `not_applicable`, `inconclusive`), `checks`, `evidence`, and an optional `detail`. Evidence entries have `subject`, `expected`, `observed`, `detail`, and `exchange_id`.

## Reproduction

`rule`, `original_steps`, `reduced_steps`, `attempts`, `successful`, `label` (`reduced reproduction` or `reduction unsuccessful`), `duration_ms`, `recording` (the reduced file or null), and `steps`, each with `id`, `method`, `path`, `tags`, optional `body`, and `quantity_reduced`.

## Agent

`model`, `rounds`, `max_rounds`, `budget_usd`, `cost_usd`, token counts (`input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`), `proposed`, `valid`, `executed`, `kept`, `stop_reason` (`no_new_cases`, `budget`, `max_rounds`, `no_valid_cases`, `model_refusal`, `error`, or `aborted` when SIGINT or SIGTERM stopped the loop at a case boundary), `prompt_versions`, `transcript_path`, `cases_path`, and `cases`. Each kept case has `id`, `round`, `hypothesis`, `tags`, `steps`, `repeat` (how many times the case ran on each system, 1 to 50), `dedupe_key`, `reference` and `candidate` (status and latency of the final step of the first run, or null), `latency` (exact nearest rank percentiles over the runs of each side, in the same shape as a latency summary, or null when a side failed), `error`, `diff`, `latency_breach`, and `revealed`.

## Exit codes

| Code | Meaning                                                 | Commands                                                                  |
| ---- | ------------------------------------------------------- | ------------------------------------------------------------------------- |
| 0    | pass, or a render, or the agent without a key           | all                                                                       |
| 2    | fail                                                    | `rp replay`, `rp invariants`                                              |
| 3    | inconclusive, or stopped by SIGINT or SIGTERM           | `rp replay`, `rp invariants`, and `rp shrink` and `rp agent` when stopped |
| 1    | tool error: bad flags, a missing file, a bad rules file | all                                                                       |

## Output formats

`rp report --format <name>` renders the run file in one of five formats. Without `--format` the command writes HTML when `--out` is given and the terminal summary otherwise. Every format is rendered from the run file alone, so the same run always produces the same bytes.

| Format     | Use                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `terminal` | The plain text summary `rp replay` prints. No color codes, so it reads the same in a log.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `html`     | One file with inline CSS and inline SVG, no script, no external resource. The correctness drill down shows at most 200 mismatched exchanges. They are grouped by the generalized path of their first untolerated finding, in the order of the top mismatching paths, and taken round robin across the groups in run order, so every path is represented even when one path accounts for nearly every mismatch. Each group heading says "showing N of M", and a line above the groups says how many were left out. The errors table lists at most 50 and says so. The full lists are in the run file. |
| `json`     | The run file itself, validated against the schema and pretty printed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `junit`    | JUnit XML for a CI system. See below.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `markdown` | A summary for a pull request comment or a GitHub job summary. See below.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### JUnit

`--format junit` writes one `<testsuites>` document that GitHub Actions test reporters, Jenkins, and GitLab accept. Every value from the run is escaped, control characters XML cannot carry are dropped, and nothing depends on the clock.

- One `<testsuite>` per threshold section that has rows, named `latency`, `correctness`, `errors`, `pacing`, or `invariants`, in that order. Each row is a `<testcase>` with `classname` set to the section and `name` set to the row id, such as `latency.by_tag.create-order.p99_ms`. A failed row carries a `<failure>` whose message is `measured X, limit Y`; a row that could not decide carries a `<skipped>` whose message is the row's detail, such as `3 successful samples, minimum 20`.
- One `<testsuite>` per system with invariant results, named `invariants.reference` and `invariants.candidate`, with one `<testcase>` per rule named after the rule. A violated rule carries a `<failure>` whose message is the first evidence line and whose body lists the statement and every evidence entry. An inconclusive or not applicable rule carries a `<skipped>`.
- One `<testsuite name="run">` with a single `<testcase name="verdict">`. It fails on a failing run with the failed rows in the body, is skipped on an inconclusive run with the conditions as the message, and passes otherwise. Its `<properties>` carry the run id, the verdict, the recording, the target, and the creation time.

A passing run therefore shows every case green, a failing run shows exactly the rows and rules that failed, and an inconclusive run shows what could not decide without counting it as a failure.

### Markdown

`--format markdown` writes GitHub flavored Markdown with no HTML: a heading with the verdict and the run id, the recording, target, pacing, and duration, the inconclusive conditions when there are any, the threshold table, the latency table with reference / candidate p50, p99, and max per tag, the correctness totals and the top mismatching paths, the invariant summary per system with every violated or inconclusive rule, the reproduction when `rp shrink` ran, and the agent summary when `rp agent` ran. Recorded strings have their Markdown punctuation escaped so a path or a hypothesis cannot break a table. The demo run renders in well under 150 lines. Write it to `$GITHUB_STEP_SUMMARY` for a job summary, or post it as a pull request comment.

### Exit code after a render

`rp report` exits 0 after a successful render whatever the verdict, so a pipeline can always produce the report. With `--fail-on-verdict` it exits with the run's own code instead, 0 for pass, 2 for fail, and 3 for inconclusive, after the output is written. The flag applies to every format and to `--explain`. A tool error such as a missing run file still exits 1. A pipeline that wants to render first and gate second runs `rp report` twice, or once with the flag as its last step.
